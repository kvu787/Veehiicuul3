## Functional actions

Selected checkered-line/checkpoint editing recovers V2 Source/TrackWorkspace.cpp Update/ApplyPlacement's contract: center=(a+b)/2, heading=atan2(edge.x,-edge.y) in degrees, width=length(edge), and a finite four-field candidate applied together. Width is [0.1,1000] m; endpoint coordinates stay within +/-10000 m. Heading is the directed crossing normal, with 0 degrees toward +X and 90 toward +Y. The small sidebar uses existing numeric fields, numbered gate buttons and Apply/Cancel. It keeps road boundaries built, preserves all other gates/order/curves/paints/assets, supports exact undo/redo and the existing Version 2 endpoint persistence. No-op fields or a 360-degree equivalent heading preserve original endpoints/history. Invalid active text blocks Apply; invalid endpoint placement retains the form. Cancellation and pending-save/Drive guards preserve prior authored/dirty state. Off-road applied gates disable Drive through the existing validation. Selected gate center uses the existing red selection semantic; gate/crossing colors are retained.

Model builder supports source SlopeCar/new primitive scenes, adding box/plane/cylinder cages, object/vertex/face selection, viewport picking, selected-vertex dragging, object/element numeric transforms and keyboard nudges/rotation/scale, preview subdivision levels, refinement/extrusion, material-slot copy/face assignment, all eight SimplePaint fields, numeric drag speed, relative paint dragging/cancellation, source-part paint reset, undo/redo, frame all/selected, camera orbit/pan/zoom, scene save/open and compiled C++ mesh export. Source SlopeCar is evaluated geometry; its five regions are independently paintable/transformable, while cage editing requires a primitive/cage model.

Track builder supports empty/example projects, periodic cubic outline drafts, finish/cancel, outline/control-point selection, point X/Y/weight editing, selected deletion and viewport movement, selected-outline degree and RGB numeric/relative editing, surface generation, two-point checkered-line/checkpoint placement and selected center/heading/width editing and deletion, start position/heading, model-scene vehicle/decor assets, decoration placement/position/heading/height/scale/removal, vehicle scale, stick deadzones, remove selected outline/last checkpoint, independent undo/redo, track save/open and camera controls. RGB edits preserve generated geometry and explicit unlit material identity; one completed drag adds one undo step, while cancel/no-op do not change history or clear earlier dirty state. The shared model numeric drag-speed setting also controls relative RGB drags. Degree accepts integers 1-3 below the selected outline's control-point count, matching the existing domain limit. An explicit change resets only its degree/knots to uniform periodic spacing; points, weights, colors, other outlines, assets and placements remain unchanged. The basis and shape necessarily change, without adding points or repairing track topology. Equal degree preserves authored knots exactly. Undo restores original knots, including nonuniform rational curves. Drive stays disabled until surfaces rebuild successfully. Arbitrary valid authored knots round-trip and can be edited through the bounded vector field. Camera-follow toggling is bound to the same small button in Track builder and Drive.

Explicit periodic-knot editing is bound to one application-specific vector field plus Apply/Cancel buttons. Veehiicuul2 Source/TrackWorkspace.cpp (ChangeDegree/ApplyPoint) and Documentation/TrackAndDriving.md expose uniform reset on degree change and saved-knot preservation, with no knot-vector UI. Its Racing2DTests.cpp verifies repeated nonuniform rational-circle knots. This binding fulfills the user's explicit authoring request. It accepts up to 2048 characters/71 values, validates length, finite bounds, monotonicity, period repetitions and closed seam atomically, preserves degree/points/weights/materials/placements, and supports cancel/history/save/reload. Changed boundaries invalidate surfaces. Exact equality with the currently built sampled boundary retains geometry; approximate comparisons never reuse it. Existing Version 2 reading/persistence policy remains unchanged; this editing gate adds the explicit periodic-extension check.

Drive uses the built track, original vehicle assets/paints, planar stepping, keyboard/GameInput acceleration and brake/reset/menu actions, checkpoint/lap/boundary progress, separate 3D vehicle presentation and preserved authored state on return to either editor. Physical controls, actual session notifications and input-to-panel latency remain manual gates. Each mode retains its own clamped sidebar position. V2 has an ordered checkpoint list and selected-item removal; an explicit reorder UI was not found and is not presented as recovered parity. No new framework facility is needed.

## Selected deletion parity

V2 TrackWorkspace.cpp DeletePoint erases the selected control and makes uniform knots before curve validation. Its UI allows deletion only above max(3,degree+1) controls. V3 keeps that limit, degree and surviving weights/positions/colors; it resets knots deliberately, invalidates surfaces and requires a successful Build before Drive. Curve topology/placement repair is not performed automatically. V2 DeletePlacement clears the finish flag or erases one selected checkpoint. V3 preserves the finish payload while clearing its flag, preserves remaining checkpoints and order, retains built roads and validates the remaining race requirements. No explicit reorder UI was found in V2.

Two existing buttons expose these actions. Point selection stays at the same ordinal when a following point exists, otherwise moves to the last survivor. Checkpoint selection follows the same rule; with none remaining it selects the placed finish, otherwise no gate. Deleting the finish selects the first remaining checkpoint. Track undo/redo restores exact authored controls/knots/weights/endpoints/order and recorded selection. Failed edits restore selection and keep redo history. Deletion ignores an unapplied active numeric/knot field, matching V2's Delete action instead of committing partial field text first. Selected gate deletion discards its unapplied gate form; a pending gate form blocks unrelated point deletion. Other outline/gate/color gestures must finish or cancel first. Disabled/missing/minimum actions add no history or dirty state. Undo conservatively marks authored state modified, as the existing V2/V3 policy does; successful Save/Open clears it.

## Camera-follow and independent mode views

V2 TrackWorkspace.cpp defaults following_ to false, enables its Follow the car control in Track builder and Drive, and centers camera.target at the planar car position during Tick. It changes no project/history flag. BeginDrive saves the authoring camera, preserves its target/height, sets pitch .95 and yaw 0, and EndDrive restores the exact saved view. Orbit/zoom remain available; while following, a manual pan is temporary until the next update. This is the recovered contract, not a new chase-camera or camera-animation framework.

V3 has independent model, track-authoring and Drive cameras. Drive seeds a separate camera on each new session, applies the V2 pitch/yaw convention, and immediately centers the car when follow is enabled. Enabling during Drive centers the current car without changing yaw/pitch/height or race state; disabling retains the current target. Reset car uses the existing 2D Session::Reset and updates the follow target immediately. View changes do not enter project JSON/export or authored history, dirty either asset, regenerate roads or schedule an editor timer. Follow remains an application-session preference across modes. Drive exit exposes the exact untouched editor camera. Selecting the already active mode keeps race/view/input/clock state instead of restarting them. Framing in Drive changes only its separate camera.

Domain and own-HWND routed tests cover defaults, editor arming, partial numeric cancellation, preservation of unapplied gate forms, follow/free movement, orbit/pan/zoom, exact editor restoration, reset, active/repeated Drive, direct exits to both editors, generated storage and clean authored/history state. Synthetic suspension in both follow/free modes stops ticks/presents; zero-elapsed resume preserves exact race/view state. Actual physical input and OS pause/resume notification delivery remain manual. Per-mode sidebar positions are now restored and clamped independently.

## Sidebar restoration

V2 Application::LayoutInspector/SetMode keeps the model panel's scroll_ when hidden. TrackWorkspace::BeginDrive saves editingScroll_ and starts its compact Drive panel at zero; EndDrive restores editingScroll_. V3 retains a separate runtime offset for Model builder, Track builder and Drive as explicitly requested. The shipped compact Drive panel fits and therefore clamps to zero. It will retain its own nonzero offset if content exceeds the panel; no filler controls or permanent timer were added.

Interface clamps and records the current mode's offset whenever content changes. A successful mode change restores that mode's saved position and rebuilds controls immediately before another input can hit them. Shrink clamps become the saved value and are not resurrected when content grows. Wheel, captured scrollbar movement, rail paging and numeric reveal shift clipped control rectangles immediately, so multiple input messages before a frame use the same coordinates as drawing. Popup lookup follows the same topmost order as hit testing.

Opening Mode preserves unapplied numeric/knot text and pending gate forms. Selecting the current mode keeps drafts and scroll. An actual transition cancels unapplied field/form drafts through the existing Abort path; invalid or disabled Drive consumes the popup press without committing a field or clicking the underlying panel. Outline/two-point placement drafts keep their existing domain guards. Scroll is absent from authored JSON/export/history, does not rebuild road/mesh geometry, and an unchanged wheel at a bound does not invalidate a frame. No polling or animation was introduced.

## Remaining V2-to-V3 scope inventory

This is a bounded audit of the actual stopped V2 command handlers, not a new feature wish list. Application.cpp Command/Key and TrackWorkspace.cpp Command/BeginDrive/EndDrive were compared with App.cpp Command/Pointer/Key and Editor.cpp. Core model/material/track/racing/persistence workflows in the table above are integrated and tested. The following legacy functions or behavioral differences remain; the earlier description of scroll as the only functional gap was incomplete.

| Verification         | Physical device/OS/scanout checks were not completed in V2    | Still pending; automated injection is not physical validation   |

Small existing defaults also differ: added shapes use the origin/current default paint instead of V2's view-center/name defaults; new outlines use V3's current neutral surface colors/names. These are observable migration differences, not missing geometry/persistence capability. Numeric transforms commit individual fields rather than V2's Apply form, paint numeric commits use Enter/leave instead of partial live previews, and start/decor headings are labeled radians rather than V2's degrees. The custom UI and fixed 2560x1440/100% presentation are explicit user-directed architecture/presentation changes.

No checkpoint reorder UI was found in V2. Generalized import, symmetry, creases, loop cuts, opponents and a full game were already absent. Tab/accessibility/IME/access keys/general widget toolkit/docking/themes are explicitly excluded from this rewrite scope. Physical mouse/keyboard/gamepad/global clipboard, real notification delivery, actual consumed-GameInput-to-ETW display association and electrical power remain unverified. Additional automated RGB selection-change-during-gesture and numeric black/white framebuffer cases remain test-coverage gaps. Closing the rewrite should resolve or explicitly accept these finite legacy differences and manual limits, not add framework facilities.
