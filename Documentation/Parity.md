Application workflow gaps to close progressively: editable track surface colors/degree/knots, gate endpoint editing/reordering beyond placement/remove-last, camera-follow toggle, and broader negative native input/capture/focus integration tests. Selected-part framing is now bound to a custom button and Shift+F; F retains Frame all. This affects the camera only, respects the part's transform and supports source evaluated SlopeCar parts. Track point drags currently clear built surfaces; build again before Drive. Numeric edits commit on Enter or clicking elsewhere, rather than continuously previewing each partial string. History is bounded to 128 completed edits to keep resource growth bounded. Drafts and cameras remain authored mode state; per-mode sidebar scroll restoration is still pending. Existing generalized import, creases, limit-surface editing, symmetry, loop cuts and complete game features were already absent in Veehiicuul2 and remain outside this milestone.

## Functional actions and next binding

Model builder supports source SlopeCar/new primitive scenes, adding box/plane/cylinder cages, object/vertex/face selection, viewport picking, selected-vertex dragging, object/element numeric transforms and keyboard nudges/rotation/scale, preview subdivision levels, refinement/extrusion, material-slot copy/face assignment, all eight SimplePaint fields, numeric drag speed, relative paint dragging/cancellation, source-part paint reset, undo/redo, frame all/selected, camera orbit/pan/zoom, scene save/open and compiled C++ mesh export. Source SlopeCar is evaluated geometry; its five regions are independently paintable/transformable, while cage editing requires a primitive/cage model.

Track builder supports empty/example projects, periodic cubic outline drafts, finish/cancel, outline/control-point selection, point X/Y/weight editing and viewport movement, surface generation, two-point checkered-line/checkpoint placement, start position/heading, model-scene vehicle/decor assets, decoration placement/position/heading/height/scale/removal, vehicle scale, stick deadzones, remove selected outline/last checkpoint, independent undo/redo, track save/open and camera controls. Existing arbitrary valid NURBS degrees/knots and colors round-trip in the domain format but lack numeric UI binding. Gate endpoint/reorder operations and camera-follow toggling are likewise remaining authoring/presentation bindings.

Drive uses the built track, original vehicle assets/paints, planar stepping, keyboard/GameInput acceleration and brake/reset/menu actions, checkpoint/lap/boundary progress, separate 3D vehicle presentation and preserved authored state on return to either editor. Physical controls, actual session notifications and input-to-panel latency remain manual gates. The next smallest meaningful authoring gap is outline surface RGB editing using the existing numeric controls and track history/persistence, followed by degree/knots and gate endpoint operations. No new framework facility is needed.

The user deliberately excluded Tab navigation, accessibility providers/screen-reader integration and broad UI framework replication. Those are scope omissions, not open delivery gates. IME/rich text, access-key infrastructure, docking, elaborate themes/transitions and a general toolkit are also excluded. Numeric fields accept ASCII decimal/scientific forms; source names render through DirectWrite, but arbitrary name editing is not exposed.

Visible automated verification does not establish physical pointer/gamepad usability or real panel scanout timing. The background test owner never activates; cursor operations are simulated. No claim of faster UI or lower electrical power than the native reference is made.
