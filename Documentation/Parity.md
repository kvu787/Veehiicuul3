## Functional actions and next binding

Model builder supports source SlopeCar/new primitive scenes, adding box/plane/cylinder cages, object/vertex/face selection, viewport picking, selected-vertex dragging, object/element numeric transforms and keyboard nudges/rotation/scale, preview subdivision levels, refinement/extrusion, material-slot copy/face assignment, all eight SimplePaint fields, numeric drag speed, relative paint dragging/cancellation, source-part paint reset, undo/redo, frame all/selected, camera orbit/pan/zoom, scene save/open and compiled C++ mesh export. Source SlopeCar is evaluated geometry; its five regions are independently paintable/transformable, while cage editing requires a primitive/cage model.

Track builder supports empty/example projects, periodic cubic outline drafts, finish/cancel, outline/control-point selection, point X/Y/weight editing and viewport movement, selected-outline degree and RGB numeric/relative editing, surface generation, two-point checkered-line/checkpoint placement, start position/heading, model-scene vehicle/decor assets, decoration placement/position/heading/height/scale/removal, vehicle scale, stick deadzones, remove selected outline/last checkpoint, independent undo/redo, track save/open and camera controls. RGB edits preserve generated geometry and explicit unlit material identity; one completed drag adds one undo step, while cancel/no-op do not change history or clear earlier dirty state. The shared model numeric drag-speed setting also controls relative RGB drags. Degree accepts integers 1-3 below the selected outline's control-point count, matching the existing domain limit. An explicit change resets only its degree/knots to uniform periodic spacing; points, weights, colors, other outlines, assets and placements remain unchanged. The basis and shape necessarily change, without adding points or repairing track topology. Equal degree preserves authored knots exactly. Undo restores original knots, including nonuniform rational curves. Drive stays disabled until surfaces rebuild successfully. Arbitrary valid authored knots round-trip and can be edited through the bounded vector field. Gate endpoint/reorder operations and camera-follow toggling remain authoring/presentation bindings.

Explicit periodic-knot editing is bound to one application-specific vector field plus Apply/Cancel buttons. Veehiicuul2 Source/TrackWorkspace.cpp (ChangeDegree/ApplyPoint) and Documentation/TrackAndDriving.md expose uniform reset on degree change and saved-knot preservation, with no knot-vector UI. Its Racing2DTests.cpp verifies repeated nonuniform rational-circle knots. This binding fulfills the user's explicit authoring request. It accepts up to 2048 characters/71 values, validates length, finite bounds, monotonicity, period repetitions and closed seam atomically, preserves degree/points/weights/materials/placements, and supports cancel/history/save/reload. Changed boundaries invalidate surfaces. Exact equality with the currently built sampled boundary retains geometry; approximate comparisons never reuse it. Existing Version 2 reading/persistence policy remains unchanged; this editing gate adds the explicit periodic-extension check.

Drive uses the built track, original vehicle assets/paints, planar stepping, keyboard/GameInput acceleration and brake/reset/menu actions, checkpoint/lap/boundary progress, separate 3D vehicle presentation and preserved authored state on return to either editor. Physical controls, actual session notifications and input-to-panel latency remain manual gates. The next core binding is selected checkered-line/checkpoint placement editing (V2 supports center, heading and width), followed by checkpoint ordering and the camera-follow toggle. No new framework facility is needed.

The user deliberately excluded Tab navigation, accessibility providers/screen-reader integration and broad UI framework replication. Those are scope omissions, not open delivery gates. IME/rich text, access-key infrastructure, docking, elaborate themes/transitions and a general toolkit are also excluded. Numeric fields accept ASCII decimal/scientific forms; source names render through DirectWrite, but arbitrary name editing is not exposed.

Visible automated verification does not establish physical pointer/gamepad usability or real panel scanout timing. The background test owner never activates; cursor operations are simulated. No claim of faster UI or lower electrical power than the native reference is made.
