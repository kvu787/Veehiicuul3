# Verification and platform boundaries

First milestone Release build passes 29 noninteractive checks plus two displayed CTest checks (31 total): ported domain/assets/persistence/compiled exports, SimplePaint contract/hardware/WARP, GameInput runtime and edge handling, consumed display input/clock/protocol/ETW lifecycle, plus new shared UI state/controller and hidden/displayed GPU integration tests. Debug passed all 28 initial noninteractive checks; the added DirectWrite coverage/cache/resource test is included in the 29-check committed-source packaging gate. Snapshot manifests identify exact committed source and copied executable hashes; development logs are Git-ignored.

NE18NZ2 was measured as BOE0D5B / NE180QAM-NZ2 on DISPLAY1, physical desktop (5120,-958)-(8960,1442), 3840x2400, effective DPI 96x96. Its black margins are 640 horizontal and 480 vertical. Pure state tests cover exact 2560x1440 thresholds, either dimension below threshold, 125%/unequal scaling, negative origins, black-margin hit rejection, clipping, numeric malformed/nonfinite rejection, clipboard-form validation, scrollbar synchronization and idle/minimize/occlusion scheduling.

Displayed hardware/WARP checks compare every center pixel against the full-resolution internal capture within one output byte of tolerance and require every margin pixel to be black. Test windows use no-activation styles and never focus/capture/warp/hide the physical pointer. Foreground/focus/capture are observed as stable on the displayed runs. User cursor movement is recorded rather than falsely attributed to the test. Shader drag ownership runs against a fake platform in automatic tests; actual physical raw-relative mouse delivery is pending.

The 3-second static displayed hardware and WARP runs each recorded zero new presents, one deadline wake, zero process CPU milliseconds at Windows' accounting resolution, and zero DX12 debug warnings/errors. Hidden runs likewise recorded zero presents. The clean application waits indefinitely without including DXGI's already-signaled frame handle; the tests use a finite observation deadline. No electrical GPU/CPU power, prolonged battery/resource profile or comparison with native controls was measured.

Consumed GameInput timestamps and Present probe metadata were ported unchanged. UI/presentation changes do not turn ETW protocol/lifecycle success into physical input-to-display evidence. No controller was selected during these runs. Actual display matching and physical gamepad/display latency remain pending.

Builds and headless/UI-domain/hidden GPU checks continue on a locked desktop while the machine is awake and connected. Visible checks inspect the input desktop and return skip code 77 when unavailable; packages then remain candidates. No security, power or resolution setting is changed. A sandboxed first Ninja/compiler probe stalled and was interrupted; Visual Studio build/test commands ran outside that sandbox after automatic approval.

DirectWrite rasterization uses its bitmap render target and platform shaping. Cached coverage is uploaded into a 2048x2048 R8 DX12 atlas; GPU triangles draw rectangles/text in order, clipped against the same bounds as hit testing. Per-backbuffer uploads are reused after fences, and atlas updates execute in order on the same DX12 command queue. One offscreen color/depth surface and a final centered presentation pass separate the application image from monitor dimensions. There is no D3D11, D3D11On12 or Direct2D GPU dependency. The original SimplePaint module and runtime licenses/provenance remain available in source and snapshots.
