## Independent review corrections

The original frozen 3fa40472ce0f snapshot exposed four core issues in independent source review despite its passing test gates. It is preserved as historical evidence and must not be recommended for unsaved authoring. Local source fixes mark changed committed paint and R/S transforms unsaved; cancel and unchanged gestures preserve the previous dirty state. App-level hardware/WARP tests create clean saved and opened models and exercise these paths. Cursor restoration now uses the existing integer visible-area helper with valid bounds even for 1-4 pixel intersections; release and Escape use the same code and simulated ownership. Shared button/scrollbar capture loss is tested without a focus-loss message and cannot activate or keep dragging afterward.

Visibility uses event-driven platform signals rather than flip-discard Present return codes. The actual production Run/Pump implementation is exercised for bounded static idle and driving, both with and without an instrumented Present probe. Injected show, minimize, session lock, console display-off, DWM cloak and suspend signals must stop steps and presents even after WM_PAINT, wait efficiently, then resume. Tests register the real notification services but inject state only into this app; no OS settings/session state are changed. Instrumented submissions are not a physical ETW/display validation. Hidden test windows can present to their own swapchain while testing the production driving path; static idle still must add zero presents. Arbitrary overlapping-window compositor visibility and individual-panel power state are not exhaustively known; see Architecture.md for the exact signal boundary.

The bounded rereview added cached input-desktop resumption and continuous timing checks. Unlock, console/remote reconnect and WTS_SESSION_DESKTOP_READY refresh the observed input desktop; a still-unavailable query keeps drawing blocked. A temporary test sender posts solely to this application's window. One continuous Pump call processes a spaced 200 ms suspension and resumption, then another receives back-to-back posted lock/unlock messages. Their handling in one message-drain batch is not guaranteed by the test sender. Both ordinary and instrumented Present cases require no paused steps/presents and a zero-elapsed first resumed Tick. Source clock-reset state survives a message batch, preventing simulation catch-up even if both transitions arrive before the next loop iteration. OS notification delivery and physical lock/unlock behavior remain manual checks.
