# Veehiicuul3

Windows 11 x64 C++20 / DirectX 12 rewrite with a small application-specific GPU UI. It starts with the actual embedded SlopeCar, supports subdivision cage modeling and selected-face paint slots, NURBS track authoring, and integrated planar driving. This is the first runnable migration milestone; see Documentation/Parity.md for remaining workflow and verification gaps.

All in-app controls, menus, scrollbars and text fields are application state rendered by DX12. DirectWrite supplies CPU text shaping/rasterization. Win32 supplies the window, input, raw relative mouse, cursor ownership, clipboard and standard file dialogs. No Common Controls UI or general widget framework is used. Tab navigation and accessibility providers are deliberately omitted at the user's request.

The application renders an actual fixed 2560x1440 offscreen image. A borderless window covers the selected monitor and centers that image unscaled, with inactive black margins. Startup exits with an error unless the selected monitor is at least 2560x1440 and exactly 100% scaling (effective DPI 96x96). It changes no display settings. Normal launches use Windows' primary monitor. Pass -Monitor NE18NZ2 to either PowerShell launcher for the test monitor, or an exact DISPLAY device/name for another user-selected monitor.

RunLatestBuild.cmd selects the latest verified immutable snapshot under Git-ignored TestBuilds. Development builds use Run.cmd. A named candidate can be selected explicitly through RunLatestBuild.ps1 -Candidate Candidate_directory; it never replaces LatestReady automatically. Each snapshot includes its own Run.cmd, executable, portable GameInput runtime, license notices, examples, full commit/hash manifest and verification evidence. Use Save As outside its read-only folder.

Build with Build.cmd -ConsoleTests. This runs headless state/domain and hidden offscreen hardware/WARP checks, including on a locked desktop. Build.cmd -Test also runs bounded displayed checks exclusively on NE18NZ2; a locked input desktop skips these gates. Installed Visual Studio C++ Build Tools, Windows SDK and CMake/Ninja are used; no dependency installation is needed. PublishBuild.ps1 packages clean committed source and leaves candidates unready unless copied displayed checks are explicitly requested and pass.

Choose the first menu, Mode, for Model builder, Track builder or Drive. Unsaved model and track projects and separate undo/redo histories survive mode changes. The sidebar scrolls with its wheel or scrollbar; each mode uses the same control behavior. Fields select their numeric value on click: type a decimal/scientific value, press Enter to apply, Escape to cancel. Home/End, arrows, Backspace/Delete and Ctrl+A/C/X/V edit the active numeric field. No Tab traversal is implemented.

In Model builder, choose a source part or click a surface. Its eight SimplePaint inputs appear below the transforms/material section. Scroll down to see them. Dragging a paint slider hides the cursor, uses unbounded raw horizontal mouse counts and restores it at the visible slider on release; Escape cancels. Drag speed is numeric only, from 0.0001 to 10. Physical raw-device verification remains pending. Source SlopeCar parts preserve evaluated source geometry and support whole-part transforms/paint; cage operations are disabled for those parts. Add a box/plane/cylinder or choose File > New primitive scene for vertex/face editing. Select a face, copy a material slot and assign it to that face. Preview, refine, extrude, persistence and C++ export preserve assignments. Ctrl+Z/Y undo/redo. Right drag orbits, middle drag pans and the wheel zooms. Frame selected or Shift+F fits the selected part; Frame all or F fits the whole model without changing authored data. Cage vertices drag in the view plane; arrows and PageUp/PageDown nudge local axes. R rotates, S scales and E extrudes a selected control face.

In Track builder, Example circuit provides a usable authored track. For an empty track, draw and finish periodic cubic NURBS outlines in ground, outer-road, island order. Select controls to move them or edit X/Y/weight, then build surfaces. Place a vehicle start and two-point checkered line/checkpoint gates. Copy the model scene as a vehicle/decoration asset and place/edit decorations. Saving stores current Version 2 JSON assets and authored controls. Other format versions remain unsupported.

Select Checkered line or a numbered Checkpoint in the sidebar to edit its center X/Y, heading in degrees and width in meters. Heading follows the crossing arrow: 0 degrees points toward +X, 90 toward +Y. Enter or leaving a numeric field updates the pending form; Apply gate validates and commits all four fields together. Width is 0.1-1000 m; endpoints must remain within +/-10000 m. Finite headings wrap by 360 degrees. Invalid active text blocks Apply; invalid endpoint placement keeps the form editable. Cancel gate edit, Escape, focus loss, mode change or selecting another gate discards the form. Save and Drive require applying or cancelling it first. Gate edits preserve built road surfaces, and undo/redo restores exact endpoints. An applied off-road gate disables Drive until corrected. Examples/GatePlacements.track contains a saved edited circuit.

Delete selected control point removes that point, preserves the remaining positions/weights and degree, and resets the outline's knots to uniform periodic spacing. It changes shape: Build surfaces again before Drive. At least max(3,degree+1) controls must remain, matching V2's deletion limit. Delete selected gate removes only the chosen checkpoint, or clears the checkered line's placed flag. Checkpoint order and built roads remain; Drive needs a checkered line and at least one valid checkpoint. Selection moves to the following survivor, otherwise the previous; deleting the checkered line selects the first remaining checkpoint. Undo/redo restores authored data and recorded selection. The delete buttons discard an active unapplied numeric/knot field; gate deletion also discards its unapplied gate form. Cancel outline/gate/held color gestures first. Examples/TrackDeletion.track contains a saved curve/checkpoint deletion with a valid rebuilt road.

Select an outline to edit NURBS degree. Integers 1-3 are supported, each below its control-point count. Changing degree regenerates uniform periodic knots and changes curve shape while preserving control positions, weights, colors and placements. Build surfaces again before Drive; invalid track topology is reported instead of repaired silently. Re-entering the same degree preserves existing knots. Undo restores the original degree/knots. Examples/OutlineDegree.track contains a saved edited circuit.

The selected outline also has one periodic-knot vector field. Click it to select the whole vector; type or paste decimal/scientific numbers separated by spaces or commas. Enter, Apply knot vector or clicking elsewhere validates and applies the complete vector. Escape, Cancel knot edit, focus loss and mode changes discard the draft. Rejected text stays editable and blocks selection clicks until corrected or cancelled. Home/End, arrows, selection and clipboard keys work across the full vector; its display follows the caret in a bounded horizontal window. Maximum text is 2048 characters. No table or spreadsheet is involved.

For N controls and degree p, supply N+2*p+1 finite nondecreasing values within +/-100000. The positive period is k[N+p]-k[p]; every extension must repeat k[i+N]=k[i]+period for i=0..2*p, within a floating-point tolerance. The evaluated seam must also close. Repeated knots are allowed, including the saved rational-circle form. Applying knots preserves degree, control positions/weights, colors and placements. Knot spacing can change curve shape; changed sampled boundaries require Build surfaces before Drive. Equivalent numeric vectors do nothing; built geometry stays available only when the new sampled boundary is exactly identical. Examples/OutlineKnots.track contains a saved nonuniform edited circuit.

Select a track outline and scroll to Surface color (unlit sRGB). Its RGB fields and relative sliders accept the full [0,1] range, including exact black and white. Numeric edits commit on Enter or clicking elsewhere; Escape cancels. Drag release commits one undo step; Escape, capture/focus loss and mode changes cancel a held gesture. Relative RGB dragging uses the Model builder's numeric Drag speed setting. Color-only edits preview immediately, keep built surfaces available for Drive and persist in the existing track ColorSrgb fields. They do not change vehicle/decor SimplePaint materials. Examples/OutlineColors.track in new snapshots provides a saved edited circuit.

Choose Drive after building a valid track. WASD/arrows accelerate, Space brakes, R resets; right stick/left trigger/X use GameInput. Escape or the controller Menu button returns to Track builder. Driving's spatial/core logic is entirely 2D; the renderer separately presents its pose in 3D. Checkpoint/circuit progress is available; no timer or opponents are required. Optional --trace-display-seconds 1..60 retains consumed GameInput reading timestamps and Present/PresentMon ETW association code. Actual physical display/input latency remains pending.

Static editing waits on messages and renders only invalidated frames. Driving updates while active; minimized, inactive or occluded work suspends. Tests recorded zero new presents over three seconds of static displayed UI, with one deadline wake and zero reported process CPU milliseconds at Windows' accounting resolution. These are bounded measurements, not proof of lower power than native UI. See Documentation/Verification.md.
